# US-05 – Upgrade and keep customizations

| | |
|---|---|
| Priority | Must have |
| Persona | Customer admin |
| Skill | `upgrade-check` |
| Cards | Upgrade impact report, Approval |

**User story:** As a customer admin, I want to see which of our customized screens a new release affects, so I can upgrade without losing our changes.

**Acceptance criteria (PRD):** Each customized screen is listed with what changed, a risk level and a suggested action. The agent can suggest a combined version for review. Nothing is saved without approval.

## Flow
`check_esm_upgrade_impact → (developer surface) merge proposal for review`

Every change follows the golden rules in PLAYBOOK.md (preview → explicit approval → commit → verify → summary with log id).

## Test script (done when every line passes)
1. [ ] Ask: "What will the next upgrade affect?".
2. [ ] Report lists customized screens with change, risk, action.
3. [ ] Ask for a combined version of one screen → proposal file, nothing deployed.

## Evidence to record (docs/test-results.md)
Request text · tool calls (inputs/outputs) · card shown · approval given · result · verification · change log / job id.
