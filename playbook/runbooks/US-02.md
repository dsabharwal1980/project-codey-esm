# US-02 – Settings health check

| | |
|---|---|
| Priority | Must have |
| Persona | Consultant |
| Skill | `settings-health-check` |
| Cards | Health check report, Approval |

**User story:** As a consultant, I want to check whether the org has the quoting settings and other settings ESM needs, so I find problems before they cause errors.

**Acceptance criteria (PRD):** Each setting shows as OK, Warning or Needs Fix, with the reason and a help link. The check covers settings for adding assets to a quote and performance settings. Nothing changes unless I approve a fix.

## Flow
`check_esm_setup scope=all → (Fix it) apply_esm_change preview → approve → commit → check_esm_setup scope=<area>`

Every change follows the golden rules in PLAYBOOK.md (preview → explicit approval → commit → verify → summary with log id).

## Test script (done when every line passes)
1. [ ] Ask: "Check if my setup is correct".
2. [ ] Report returns in < 2 min with counts and rows incl. 'assets' and 'performance' areas.
3. [ ] Every row has reason + help link.
4. [ ] Press Fix it on one row → Approval card → approve → re-check shows OK.
5. [ ] Confirm Codey Change Log shows Previewed → Committed for that fix only.

## Evidence to record (docs/test-results.md)
Request text · tool calls (inputs/outputs) · card shown · approval given · result · verification · change log / job id.
